Where's the Loo — App Map

A take-home guide to the finished code. Snapshot of the repository at the end of the build; it can drift as the code changes. Run again with node src/server.mjs and open http://localhost:3000.

What it is, in one paragraph

One page that shows the three nearest public toilets in Korea and greys out the ones that are closed at the chosen time. Four pieces: a shipped CSV of 33,820 toilets, an hours reader that turns free-text opening hours into open / closed / unknown, a one-file Node server that answers "which three are nearest?", and the page that draws pins, cards and a time dial.

One action, end to end: "tap a demo spot, drag the dial to 22:00"

Reference route (three stops)

Labelled a reference route: it was prepared from the finished code, not walked interactively with the learner.

  1. Input — public/app.js, search for async function find(. The demo-spot button (or the Geolocation callback) calls it with a latitude and longitude; it fetches /api/nearest and stores the three results with their parsed hours.
  2. Logic — src/lib/hours.mjs, parseHours and statusAt. The regex RANGE_RE finds time ranges; statusAt compares minutes-since-midnight with the first range, including overnight spans. Its tests: test/hours.test.mjs.
  3. Result — public/app.js, function render(). Builds the three cards with class is-open / is-closed / is-unknown and re-sets each pin's icon; public/style.css under .card.is-closed is where "grey" is defined.

To change this, start here

Show more than three toilets

public/app.js → the fetch URL in find() uses n=3; the server caps n at 10 in src/server.mjs.

Add a demo spot

public/app.js → the DEMO_SPOTS array at the top. Check first with curl 'localhost:3000/api/nearest?lat=…&lng=…' that the spot shows a grey card at the hour you want to demo.

Teach the hours reader a new spelling

src/lib/hours.mjs → ALWAYS_WORDS for always-open words, RANGE_RE for new range shapes. Add a case to test/hours.test.mjs first, then run npm test and node scripts/stats.mjs to see how many rows change.

Change what counts as "closed" in the footer fact

src/lib/toilets.mjs → factMinutes (22:00) and contrastMinutes (15:00) in loadToilets(); the page reads them from /api/meta.

Change colours

public/style.css → the tokens under :root.

A practice to reuse

Test the risky data path before the UI exists. The only real unknown in this project was the free-text hours column. Slice 1 of devpost/checklist.md built parseHours, its tests, and scripts/stats.mjs before any HTML. Running the stats script against all 24,321 rows immediately exposed two problems the unit tests had not: month spans like 하절기(7~9월) being read as 07:00~09:00, and exact duplicate rows. Both were fixed while the fix was one file wide. On another project: whatever column or API response you are least sure about, write the parser and a counting script for it first, and let its numbers decide the demo.
